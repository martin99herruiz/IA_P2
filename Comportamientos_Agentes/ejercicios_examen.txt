EJERCICIO 1 — Técnico obligado a pasar por al menos una casilla 'H' (hielo)
             para llegar a la meta (nivel 3 / nivel 5)
================================================================================

ENUNCIADO
---------
Modifica el comportamiento del Técnico en el Nivel 3 para que, al navegar
hasta la Belkanita con A*, el camino pase obligatoriamente por alguna casilla
de tipo 'H' (hielo), aunque el camino directo no pase por allí.

ANÁLISIS {

--------
La solución más limpia es un A* EN DOS FASES:
  Fase 1: A* desde posición actual hasta la 'H' más cercana (waypoint).
  Fase 2: A* desde el estado final de la fase 1 hasta la Belkanita.

Clave: usar ApplyTecnico (ya implementado) para simular el estado exacto
(posición + orientación + zapatillas) al llegar a la casilla H. Así la
fase 2 parte del estado correcto.

No hay que modificar el A* ni sus estructuras: sólo cambiar qué se le pide.

CÓDIGO — modificar ComportamientoTecnicoNivel_3
-----------------------------------------------
Reemplazar el bloque "if (!hayPlan) { ... }" por:

    if (!hayPlan)
    {
        // Buscar todas las casillas 'H' conocidas en el mapa
        vector<pair<int,int>> celdasH;
        for (int f = 0; f < (int)mapaResultado.size(); f++)
            for (int c = 0; c < (int)mapaResultado[0].size(); c++)
                if (mapaResultado[f][c] == 'H')
                    celdasH.push_back({f, c});

        EstadoT inicio;
        inicio.site.f    = sensores.posF;
        inicio.site.c    = sensores.posC;
        inicio.site.brujula = sensores.rumbo;
        inicio.zapatillas = tiene_zapatillas;

        EstadoT fin;
        fin.site.f    = sensores.BelPosF;
        fin.site.c    = sensores.BelPosC;
        fin.site.brujula = sensores.rumbo;
        fin.zapatillas = false;

        list<Action> mejor_plan;
        int mejor_long = INT_MAX;

        for (auto [hf, hc] : celdasH)
        {
            // Waypoint: la H con cualquier orientación de llegada
            EstadoT waypoint;
            waypoint.site.f    = hf;
            waypoint.site.c    = hc;
            waypoint.site.brujula = sensores.rumbo; // ignorado por EsDestino
            waypoint.zapatillas   = false;

            // Fase 1: inicio → H
            list<Action> plan1 = AEstrellaTecnico(inicio, waypoint);
            if (plan1.empty()) continue;

            // Simular el estado real al llegar a H aplicando cada acción
            EstadoT estado_en_h = inicio;
            for (Action a : plan1)
                estado_en_h = ApplyTecnico(a, estado_en_h);

            // Fase 2: H → Belkanita
            list<Action> plan2 = AEstrellaTecnico(estado_en_h, fin);
            if (plan2.empty()) continue;

            int longitud = (int)plan1.size() + (int)plan2.size();
            if (longitud < mejor_long)
            {
                mejor_long = longitud;
                mejor_plan = plan1;
                mejor_plan.splice(mejor_plan.end(), plan2);
            }
        }

        if (!mejor_plan.empty())
        {
            plan = mejor_plan;
            VisualizaPlan(inicio.site, plan);
            hayPlan = true;
        }
    }

RAZONAMIENTO
------------
- ApplyTecnico ya está en la clase → se reutiliza sin escribir código extra.
- Iterar por todas las H y quedarse con el plan más corto es O(|H| * coste_A*).
- Si no hay ninguna 'H' accesible, plan queda vacío → IDLE (comportamiento seguro).
- Para N5: aplicar el mismo patrón en la fase T5_YENDO_OBJETIVO, añadiendo

VARIANTE: cambiar 'H' por 'X', por 'S', por cualquier tipo → sólo cambia

CÓDIGO — modificar EsAccionAplicableTecnico
--------------------------------------------
Añadir al principio del bloque "if (accion == WALK)":

    bool ComportamientoTecnico::EsAccionAplicableTecnico(
            Action accion, const EstadoT &st) const
    {
        if (accion == TURN_SR || accion == TURN_SL)
            return true;

        if (accion == WALK)
        {
            // *** RESTRICCIÓN: solo movimiento cardinal ***
            Orientacion br = st.site.brujula;
            if (br == noreste || br == sureste ||
                br == suroeste || br == noroeste)
                return false;   // diagonal prohibida

            EstadoT next = NextCasillaTecnico(st);
            if (!EsCasillaTransitableTecnico(next.site.f, next.site.c,
                                             st.zapatillas))
                return false;

            int diff = abs((int)mapaCotas[next.site.f][next.site.c]
                         - (int)mapaCotas[st.site.f][st.site.c]);
            return diff <= 1;
        }

        return false;
    }

  simultáneamente sin tocar más código (reutilización garantizada).
- Los giros siguen siendo libres: el Técnico puede girar hasta quedar en

- IMPLICACIÓN para N5: el Técnico también llega al objetivo en cardinal,

EJERCICIO 8 — Nivel 4/5: diseño de tuberías más corto que NO pasa por 'S'
             + probar en Nivel 5 con agentes modificados
================================================================================

ENUNCIADO
---------
Modifica el algoritmo de búsqueda del Nivel 4 para obtener el diseño de
tuberías más corto que NO pase por ninguna casilla de tipo 'S' (sendero/arena).
Probar en el Nivel 5 que los agentes (con la modificación en su forma de
desplazarse que aquí se indica y las nuevas restricciones sobre la línea de
tuberías) son capaces de construirla con éxito.
Completar la misión con éxito independientemente del número de instantes.

ANÁLISIS
--------
Hay UNA función que actúa como filtro canónico de casillas del plan de tuberías:
    CasillaValidaParaTuberia(int f, int c)

Esta función decide si una casilla puede formar parte de la red. Actualmente
excluye: P, M, ?, B. Añadir 'S' a esa lista es el cambio mínimo y correcto.

Ventaja clave: CasillaValidaParaTuberia es llamada por BuscarPlanNivel4,
que a su vez es usada por N4, N5 y N6 → el cambio se propaga a todos
sin tocar más código.

"Más corto": BuscarPlanNivel4 ya minimiza pasos (entre otros criterios)
mediante la poda de Pareto → no hace falta cambiar el criterio de búsqueda,
solo restringir el espacio de casillas válidas.

NOTA SOBRE "la modificación en su forma de desplazarse":
El enunciado puede combinar esta restricción de tuberías con una restricción
de movimiento del agente (por ejemplo, solo movimiento cardinal). En ese caso
aplicar TAMBIÉN el cambio de EsAccionAplicableTecnico del Ejercicio 2.
Si el enunciado no especifica restricción de movimiento, este ejercicio
requiere únicamente el cambio en CasillaValidaParaTuberia.

    // 'S' añadido: la tubería no puede pasar por sendero/arena

VERIFICACIÓN EN NIVEL 5 — sin cambios adicionales
--------------------------------------------------
El Nivel 5 llama a BuscarPlanNivel4 para obtener plan_tuberias_n5.
Al estar 'S' excluida, el plan generado evita esas casillas automáticamente.
La ejecución por fases (N5_PLANIFICAR → N5_PREPARAR_TRAMO → … → N5_TERMINADO)

EJERCICIO 10 — Técnico nivel 3: mínimo tiempo (en vez de mínima energía)
================================================================================

ENUNCIADO
---------
Modifica el comportamiento del Técnico en el Nivel 3 para que, en lugar de
minimizar la energía consumida, minimice el número de instantes de simulación
(número total de acciones: WALK + giros).

ANÁLISIS
--------
El algoritmo A* ya implementado minimiza el coste acumulado g (suma de
CosteEnergiaTecnico). Para pasar a tiempo mínimo basta hacer que cada acción
cueste exactamente 1 instante, sin importar el tipo de terreno ni si es giro
o avance. La heurística de Chebyshev sigue siendo admisible y consistente.

Por qué la heurística sigue siendo admisible con coste uniforme 1:
  - Para llegar de (f1,c1) a (f2,c2) se necesitan al menos max(|df|,|dc|)
    acciones WALK (cota de Chebyshev).
  - Los giros añaden acciones adicionales, nunca reducen el total.
  - Luego h(n) = max(|df|,|dc|) ≤ coste real → admisible.
  - Consistencia: un WALK cuesta 1 y h decrece como mucho 1 → h(n) ≤ 1+h(n').
    Un giro cuesta 1 y h no cambia (misma celda) → h(n) ≤ 1+h(n). OK.

CÓDIGO — modificar CosteEnergiaTecnico
---------------------------------------
Reemplazar el cuerpo completo de la función por:

    int ComportamientoTecnico::CosteEnergiaTecnico(

    {
        (void)accion; (void)st;
        return 1;   // cada acción (WALK o giro) cuesta 1 instante
    }

Eso es todo. No hay que cambiar AEstrellaTecnico ni HeuristicaTecnico.

RAZONAMIENTO
------------
- Con coste 1 para todo, A* se convierte en BFS uniforme: minimiza acciones.
- Los giros ya no son "gratuitos" → el A* generará caminos con menos giros
  innecesarios (más directos).
- La heurística max(|df|,|dc|) ya no sobreestima para ningún terreno.
- NOTA IMPORTANTE: con energía mínima, el Técnico evitaba agua (coste 60).
  Con tiempo mínimo, puede atravesar agua libremente si es el camino más corto.
  El Técnico puede morir si le queda poca energía y el nuevo plan pasa por agua.
  Si el examinador pide preservar también la seguridad energética, añadir la
  comprobación "if (energia <= umbral) return IDLE" al inicio del nivel.

  Añadir en EsAccionAplicableTecnico, en el bloque WALK:

PARTE 1: Ingeniero supersticioso
-----------------------------------------------------------------------

ENUNCIADO
---------
El Ingeniero en sus planes obligatoriamente debe usar un número impar de
acciones JUMP consecutivas. Modifica el algoritmo de búsqueda del Nivel 2
para reflejar este cambio. El Ingeniero debe llegar en el menor número de
instantes posible.

ANÁLISIS
--------
Restricción: cada "racha" de JUMPs consecutivos en el plan debe tener
longitud impar (1, 3, 5, …). No puede haber 0, 2, 4, … JUMPs seguidos.

Para que el BFS respete esta restricción, hay que ampliar el estado con un
campo que indique en qué situación está la racha de JUMPs actual:
  jc = 0  → libre (no hay racha activa)
  jc = 1  → racha de longitud impar (puede terminar o continuar con JUMP)
  jc = 2  → racha de longitud par  (DEBE continuar con JUMP; no puede terminar)

Transiciones:
  Estado jc=0: JUMP → jc=1,  WALK/TURN → jc=0
  Estado jc=1: JUMP → jc=2,  WALK/TURN → jc=0  (permitido: racha impar completa)
  Estado jc=2: JUMP → jc=1,  WALK/TURN → PROHIBIDO (racha par incompleta)

El destino se acepta solo cuando jc ∈ {0, 1} (no estamos en racha par).

La clave de "explorados" es (EstadoI, jc) para distinguir llegar a la misma
celda con rachas distintas.

El BFS con este estado ampliado sigue siendo BFS (coste uniforme) → el plan
encontrado es óptimo en instantes de simulación.

CÓDIGO — escribir nueva función en ingeniero.cpp (antes de Nivel_2)
--------------------------------------------------------------------
Añadir también la declaración en ingeniero.hpp:
    list<Action> B_Anchura_Supersticioso(const EstadoI &ini, const EstadoI &fin);

Implementación (añadir en ingeniero.cpp):

    list<Action> ComportamientoIngeniero::B_Anchura_Supersticioso(
            const EstadoI &inicio, const EstadoI &fin)
    {
        struct Nodo {
            EstadoI estado;
            list<Action> secuencia;
            int jc;   // 0=libre, 1=racha-impar(puede parar), 2=racha-par(debe continuar)
        };

        // Explorados: (EstadoI, jc) para distinguir rachas distintas
        set<pair<EstadoI,int>> explored;
        queue<Nodo> fifo;

        Nodo ini_nodo;
        ini_nodo.estado = inicio;
        ini_nodo.jc = 0;
        fifo.push(ini_nodo);

        while (!fifo.empty())
        {
            Nodo cur = fifo.front(); fifo.pop();

            auto key = make_pair(cur.estado, cur.jc);
            if (explored.count(key)) continue;
            explored.insert(key);

            // Aceptar si llegamos al destino y la racha actual NO está en par
            if (cur.estado.site.f == fin.site.f &&
                cur.estado.site.c == fin.site.c &&
                cur.jc != 2)
                return cur.secuencia;

            for (Action a : {WALK, JUMP, TURN_SR, TURN_SL})
            {
                // Si jc==2 (racha par en curso) solo se puede hacer JUMP
                if (cur.jc == 2 && a != JUMP) continue;

                unsigned char ter = mapaResultado[cur.estado.site.f][cur.estado.site.c];
                unsigned char cot = mapaCotas[cur.estado.site.f][cur.estado.site.c];
                EstadoI next_est = applyI(a, cur.estado, ter, cot);

                // Descartar WALK/JUMP que no mueven (obstáculo o borde)
                if ((a == WALK || a == JUMP) &&
                    next_est.site.f == cur.estado.site.f &&
                    next_est.site.c == cur.estado.site.c) continue;

                // Calcular nuevo jc
                int next_jc;
                if (a == JUMP)
                    next_jc = (cur.jc == 0) ? 1 : (cur.jc == 1 ? 2 : 1);
                    // 0→1 (inicio racha), 1→2 (racha se vuelve par), 2→1 (par→impar)
                else
                    next_jc = 0;  // WALK o TURN: resetear racha

                auto next_key = make_pair(next_est, next_jc);
                if (!explored.count(next_key))
                {
                    Nodo child;
                    child.estado = next_est;
                    child.secuencia = cur.secuencia;
                    child.secuencia.push_back(a);
                    child.jc = next_jc;
                    fifo.push(child);
                }
            }
        }
        return {};  // sin solución
    }

En el bloque "if (!hayPlan) { ... }":

RAZONAMIENTO

- Se escribe una función nueva → N5 y N6 no se ven afectados.
- El BFS es FIFO (coste uniforme) → el primer plan encontrado es óptimo
